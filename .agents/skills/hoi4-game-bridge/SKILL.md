# HOI4 game bridge

Read the repository's `AGENTS.md` and `docs/hoi4-bridge/STATUS.md` first. Verify the checkout and requested branch before edits. The existing service is `server/api.ts`; reuse `server/parser.ts`, `server/importer.ts` and `server/store.ts`. The bridge contract is `src/bridge-types.ts`.

## Community source tools

The pinned `hoi4_agent_tools` MCP registration supplies ten source-analysis tools. Read `docs/hoi4-bridge/COMMUNITY-TOOLS.md` for the reviewed revision, setup, evidence and native-adapter blockers. Discover the actual catalog before invoking tools; use `workspaceId: "companion"`. Prefer `hoi4.source_lookup` for exact definitions, nested blocks and overrides; `hoi4.reference_search` followed by `hoi4.reference_read` for installed documentation; `hoi4.script_validate` for command kinds/scopes. Focus, technology, event and decision inspectors provide source analysis, not live state or eligibility. `focus_inspect` writes analysis reports to configured ignored storage (its readOnlyHint is false); game/mod source writes are excluded. Do not rebuild these developer analyzers in the companion.

Inspect `structuredContent.status`, then `data`; MCP transport success alone is insufficient. Validation `valid: null` means unresolved; `parametersChecked: false` remains a limitation even when valid is true. Preserve revision, source layer, line and scan completeness. No source-rewrite tools are enabled. If the MCP catalog is absent, use the documented diagnostic/reconnect procedure once and the existing bridge reference query as a fallback; do not install native control components or launch HOI4 to repair source-tool access.

## Application integration and complete MCP catalog

Read `docs/hoi4-bridge/MCP-CAPABILITIES.md` for all 28 standard tools plus the two private opt-ins. Only ten are enabled; prior execution evidence covers source_lookup, reference_search and script_validate, not every enabled inspector. `node scripts/bridge-community-inventory.mjs` inventories the pinned definitions without invoking tools or changing permissions. Qualify already-enabled domain inspectors before adding duplicate analysis code. Recommended render/GUI/probability permissions are proposals, not current authorization; source-writing tools remain disabled outside a specifically approved Git-tracked mod workspace.

The Command center's Campaign Intelligence panel consumes `GET /api/v1/bridge/intelligence` and the local-only `POST /api/v1/bridge/replay`. Replay validates JSONL but never writes live history or grants ownership. Imported recordings remain origin-unverified; fixtures must be labeled. M5 stores imported history separately in bridge SQLite and previews a new planner workspace; it never overwrites existing manual plans. See `docs/application/MILESTONE-5.md` for history, baseline and isolated Windows build workflows. See `docs/hoi4-bridge/TELEMETRY-INVENTORY.md` before proposing more OCR: candidate script fields remain unverified until native readback. Use `docs/application/FEATURE-INVENTORY.md` before adding another screen and `docs/application/MILESTONE-4.md` for focused UI checks. Diagnose M3 OCR from saved JSON with `python scripts/bridge-ocr-diagnose.py <ocr.json>`; it corrects spatial ordering only and cannot authorize input. No new native test is needed for dashboard or OCR-fixture work.

## Integration platform and dedicated MCP

For platform work, read `docs/hoi4-bridge/MILESTONE-7.md` and `PLATFORM-CONTRACT.md`. The application owns one GameBridge, SQLite database, action gateway and receipt store. The dedicated `hoi4_bridge_*` MCP server is a stdio adapter to that running application's authenticated loopback endpoint. Keep HOI4 Agent Tools separate for source analysis. Do not create another backend or register an execution tool to make observation tooling work.

Use `hoi4_bridge_connection`, `hoi4_bridge_capabilities` and `hoi4_bridge_observations` first. A log monitor is not owned live state. An owned connection must pass the existing profile/process/version/log checks. `hoi4_bridge_focus_research` preserves per-field qualification; missing selection and stored focus progress do not imply an active focus. Save-derived observations are persisted history, not telemetry, and never become plan assumptions automatically. Binary/compressed saves refuse; only the documented plaintext mapping is available.

The connection credential is the running build's `bridge-connection.json`, shown by the app's connection diagnostics. Pass its absolute path through HOI4_BRIDGE_CONNECTION; never paste or commit its token. SDK/stdin errors require checking that matching app and descriptor, not restarting HOI4. `hoi4_bridge_action_validate` is a dry run; retrieve receipts by request ID rather than dispatching a retry. Emergency stop latches the shared gateway and stops observation monitoring; it does not undo input or terminate a regular game.

Before any future native test, run the deadline tests in `tests/bridge-deadline.test.ts`. Keep M6.5's overrun documented. The independent supervisor must acknowledge readiness; launch failure stops only the verified owned process. Identity uses exact Windows creation FILETIME and a retained OS handle for termination. Explicit native stop, corrupt budget and elapsed wall/monotonic deadline fail closed. The M7 native plan is a proposal, not evidence or a reason to reset the exhausted M6.5 budget.

## Repeatable workflow

For reference explanation work, read `docs/application/MILESTONE-7.1.md`. Reuse `src/mechanics.ts` and `src/mechanics-interpreter.ts` across reference screens; the existing importer supplies localized names and uniquely resolved idea modifiers with provenance. Preserve conditional guards, phase, units and ROOT/FROM/PREV scope. A known requirement with unavailable campaign state is different from unsupported scripting. Dynamic titles and unresolved scripted helpers must stay explicit.

Run `node --import tsx scripts/explanation-audit.ts` to compare the fixed twelve installed decisions against `tests/fixtures/explanation-baseline-m7.json`; it refuses changed source hashes/versions. After a game update, establish a new matched baseline instead of overwriting evidence to make the comparison pass. Specific compact outcomes exclude costs, tooltips, flags and generic fallbacks; raw node counts are diagnostic, not a quality percentage. Start with `tests/explanations.test.ts`, then the affected importer/UI checks. `scripts/explanation-ui.ts` and the optional `HOI4_EXPLANATION_SMOKE=1` packaged journey exercise the same renderer without launching HOI4. Their commands and retained-recording requirements are in the report.

1. Run `npm run dev -- --bridge inspect`. This reads the installation and detected launcher configuration without opening an app database. Use explicit `HOI4_GAME_DIR` and `HOI4_USER_DIR` when automatic discovery is incomplete. Read installed `launcher-settings.json` and `documentation/`; an executable's Windows product version can be the generic `1.0`. Recheck after Steam updates.
2. Set `HOI4_DATA_DIR` to a disposable directory before indexing or testing. Run `npm run index`, then `npm run dev -- --bridge reference <identifier> [kind]`. Retain source path, line, hash, version and index revision. Resolve ambiguity instead of choosing the first candidate. The base index does not merge mods: inspect detected collisions, same-path replacement and descriptor `replace_path` before using a definition.
3. Search installed `common/national_focus`, `common/technologies`, `events`, `common/decisions`, `common/scripted_triggers`, `common/scripted_effects`, and localisation with `rg`. Parse repeated keys as ordered nodes, not a JSON object. Follow referenced effects/triggers and ROOT/FROM/THIS scopes. Extracted prerequisites, conditions and rewards do not prove eligibility or engine behavior in a campaign.
4. Query `/api/v1/bridge/status` before state-dependent work. Observer Mode cannot issue gameplay commands. Telemetry requires an explicitly configured log and `HOI4_BRIDGE_MODE=telemetry`; call `POST /api/v1/bridge/poll`. Missing values remain unavailable. Recent file writes are not proof of a running game. Replay is historical and never authorizes actions.
5. For scripts, check names/scopes against this installation's effects, triggers, dynamic-variable and localisation documentation. Use `npm run bridge:validate -- <game-root>` for this prototype's preflight. It checks syntax and required documented primitives, not general semantic correctness. Consider a separately reviewed CWTools integration for broader validation.
6. Start with `npm run test:bridge` and `npx tsc --noEmit`. Use recorded snapshots for parser/API/retry changes. Preserve existing release gates; run broad tests/build only when the change warrants them, not after every bridge iteration. Native tests are needed for script export, game UI, or adapter semantics; fixture tests cannot close those gates.
7. Before a native session, read `docs/hoi4-bridge/NATIVE-SMOKE.md` and write the budget and protected paths into the run evidence. Stop after the first isolating diagnosis, or at the stated limits. Never repeatedly launch to debug a parser defect. Categorize the blocker as environmental, permissions, unsupported-interface, version-incompatibility, scripting, integration, or application.
8. Retain raw logs/screenshots/snapshots under ignored `.bridge-local/` or `artifacts/`. Commit only concise summaries, hashes and reproducible commands. Update STATUS at meaningful milestones, including unsuccessful attempts. Never relabel a prior untested QA gate as passed.

Read `docs/hoi4-bridge/README.md` for API, replay and troubleshooting; `ADR-001.md` in that directory for reuse/control decisions. `docs/hoi4-bridge/MILESTONE-3.md` describes opt-in owned-session observation and the experimental focus adapter. Its native selection gate failed before dispatch; do not advertise native control. Inspect its saved OCR evidence offline before another bounded qualification. `scripts/bridge-owned.ts` provides owned-session diagnostics; ordinary API startup does not register it. Current focus cannot be inferred from source definitions or focus_progress (which may retain cancelled progress). Keep log freshness separate from fresh UI observation; unknown OCR remains unavailable. An emergency stop prevents later dispatch; it cannot undo earlier inputs.
