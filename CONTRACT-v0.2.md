# Knowledge Foundation contract (frozen integration interface)

The existing `companion.sqlite` remains the only store. Schema 2 is additive; profile payloads, revision CAS, tombstones and selected profile remain intact. An existing schema 0 database requires a closed-app migration with a verified backup. Never use production user data for release tests.

`src/types.ts` defines the shared DTOs. Entries retain current definition-locator `uid` and gain `entityKey = vanilla:<kind>:<semantic scope>:<id>`. Focus scope is tree ID; nested child scope is its parent key/ID. Path and localization are not identity. Repeated same logical IDs remain multiple candidates; definition UIDs receive deterministic variant suffixes only when a source repeats them. Retain all old UID -> logical-key aliases across refreshes, including removed entries. `store.resolve(reference, kind?, scope?)` reports resolved/unresolved/ambiguous/stale with all candidates and no fuzzy selection. `store.entry` returns a unique entry or undefined, preserving legacy callers.

Importer owns `server/importer.ts`, `server/knowledge.ts`, `tests/knowledge-importer.test.ts`. It can use existing `store.insert/removeSource`, which now assign identities and aliases. New `store.replaceRelationships(edges:Relationship[])` resolves typed targets and atomically replaces derived edges; call inside the import transaction after entries publish. `store.setSetting('coverage', Coverage)` publishes reconciled accounting. `data.nodes` stores ordered AST; `data.semanticScope` sets identity scope explicitly. `data.aliases` contains English search aliases. `data.localizationEvidence` records key/source/hash/line and unresolved keys. `data.constraints` retains ordered AST, operators, repeats and groups. Do not turn source declarations into engine verification. No partial commit on fatal parse/read failure. Recovered shipped syntax remains explicitly recovered. Source dependencies include localization and defines hashes. No-op refresh preserves `indexRevision`; changes to import rules, sources or applicability context change it. Importer revision 5; app version 0.2.0; db schema 2.

`Relationship` uses definition UID `from`, stable `fromKey`, typed `targetRef`, optional resolved UID `to`, resolution/reason/candidate UIDs, ordered condition AST, ordered scope path, optional repeated-key group and exact source evidence. Constraint relations may be `unsupported` if their target is a category/slot rather than an imported entity, retaining target and declaration. Inverse queries use these same edges. Conditions have unknown truth unless separately evaluated; relation resolution does not mean availability. Child entries may have a parent relation without inventing persistent game IDs for anonymous milestones. Explicitly label anonymous positional identities for revalidation.

GET `/api/v1/resolve?ref=...&kind=...&scope=...` -> Resolution (entry and candidates omit large raw script/AST in summaries).
GET `/api/v1/relationships?ref=...&direction=both|out|in&type=...` -> `{indexRevision,reference:Resolution,relationships:Relationship[],entries:Entry[]}`. Include unresolved outgoing edges and ambiguous candidates; do not truncate exact targets to fuzzy search hit limits.
GET `/api/v1/coverage` -> Coverage, with supported roots, per-source discovered/emitted/accounted records, omissions/reasons/recoveries, unsupported roots and relation resolution totals. Counts alone are not completeness.
GET `/api/v1/entries?q=...&kind=...&country=...&year=...` retains total/entries and adds indexRevision/facets; `id=...` does exact script ID lookup. English question queries map to meaningful terms, then exact relations answer unlock/recruit/event questions.
All API responses include `X-HOI4-Index-Revision`. Read metadata from the committed database on every request, not startup memory. Profiles optionally carry `referenceIndexRevision`; stale semantic plan submissions return 409 with the current revision and preserve the UI draft. Existing plain profile saves are allowed because they do not simulate semantics. Export/import remains backward compatible and adds exportSchemaVersion=2. Validate and round-trip new DLC/reference fields.

DLC metadataKnown, installed, owned, enabled and integrated are separate. Fact values yes/no/unknown each carry evidence. Metadata is not installation; file presence is not ownership. Read-only launcher disable information can establish disabled state, not entitlement. Existing profile checked DLCs stay as `legacyDlcAssertions`, a combined user assertion; do not silently manufacture two independently verified facts. New `dlcStates[id]` assertions are independent user confirmations. Preserve old fields for compatibility with v0.1.1 planning behavior but display provenance and limits.

UI worker owns `src/App.tsx`, `src/Lab.tsx`, `src/styles.css`, optional new UI components and UI tests. Integration owns types, store/migrations, API, CLI/Electron and release evidence. Keep list query/filter/page/scroll while navigating exact links; drawer Back restores prior entry and drawer scroll. Missing bookmarks must stay visible with resolution states. Show source build, extraction/uncertainty and expandable conditions/evidence. Fix wheel editing on number inputs and import error clearing. Keep save/conflict/draft controls and all laboratory correctness guards.

Developer tests are integration evidence, not independent release acceptance. External wiki audit and later desktop/game parity checks are separate. No full designer, event simulator, AI, live-data or v0.3 behavior is authorized.

## Final implementation details

- `definition:<uid>` is an explicit inspection address for a current definition after selecting a candidate. It never follows aliases. Normal references still report reused aliases as ambiguous. `data.legacyAliases` excludes any alias mapped to multiple logical keys; those keys appear in `data.ambiguousAliases` and their saved notes require review.
- Anonymous positional records add `@source:<source hash>` to their semantic scope. A file move with unchanged contents preserves identity; a source edit invalidates the old logical key and makes any reused definition UID require review. Named stable IDs keep their semantic scope across unrelated edits.
- Target refs may supply `kinds` for a typed family. Tree-scoped focus references can resolve uniquely declared global shared/joint focuses; missing/duplicate tree members remain explicit and are not selected automatically by tree assembly.
- Coverage uses an independently discovered source-record ledger (`records`), reconciled to emitted definitions and explicit omissions. Derived module-category tokens aggregate declaration evidence in a separate synthetic accounting row; they are navigation tokens, not verified engine objects or a compatibility simulator.
- Closed-app migration checkpoints and closes SQLite before copying/verifying the backup, then applies schema changes in an exclusive transaction. Failure rolls back; restoration checks the backup hash/integrity and retains its own verified pre-restore copy. The closed-services assertion remains a real prerequisite.
- Integration validation is separate from independent QA. Static installed comparisons cannot prove event scheduling, building caps, final reliability units or full mission/designer stacking. Source notes preserve narrow disagreements without importing wiki content.
