# Milestone 7 Windows acceptance

Extract the entire M7 ZIP into a new directory. Run the milestone/commit-named EXE inside win-unpacked; keep every file together. This is an unsigned isolated development application, not an installer or updater. Do not copy it over an older companion. Normal storage is `%APPDATA%/HOI4 Companion Development/M7-COMMIT/`; older build profiles stay separate. No HOI4 launch is required.

1. Open **Sources & settings**. Confirm the installed game directory and version; reindex only if your source path/version needs it. Sources are reference definitions, not your current campaign. Never replace saves, mods or launcher files to satisfy this check.
2. In **Command center > Your observed campaign**, open the bundled `M7-historical-native-recording.jsonl`. It contains eight retained M6.5 snapshots. Choose the first and last dates and inspect expanded observations. Basic Machine Tools changes from No to Yes. The recording remains historical and origin-unverified; it does not become your desktop campaign.
3. Expand **Connect game observations**. With HOI4 closed it should report disconnected. A normal game without the dedicated telemetry emitter may have no usable records. **Detected game log** or an explicit game.log path only monitors complete supported records and labels them historical unless current owned-session proof exists. Do not select an old laptop manifest on the desktop.
4. To see the save-reader UI without touching a game save, choose the bundled `M7-synthetic-save-fixture.txt` using its full path in **Plaintext save path**. It is deliberately synthetic, not a campaign recording. Alternatively select a completed disposable plaintext 1.19.4.2 save. Click **Inspect save read-only**. Check source, date, SHA256 and field qualification. Missing current-focus token stays unavailable despite stored progress. Binary/compressed saves should refuse with an explanation; do not alter personal saves to convert them.
5. Expand **Capabilities and MCP diagnostics**. Commands should be unavailable. Optional MCP clients can run the bundled HOI4-Bridge-MCP.cjs with Node >=22 and HOI4_BRIDGE_CONNECTION set to the exact local descriptor path displayed here. That credential file stays on this machine; do not share its contents. The app must remain open. See repository PLATFORM-CONTRACT.md for a configuration example.
6. Close and reopen the companion. Your imported history/save observations should remain. Automatic log reconnection is intentionally off. Hypothetical plans/manual assumptions should remain unchanged.
7. Test **Emergency stop integration** only when finished with this isolated profile: it persistently stops monitoring and blocks later commands; it does not close HOI4 or undo anything. There is no reset button in M7. Historical reading and planning still work; report accidental latching rather than editing safety state.

Report build label, Windows version, source game version, the exact step, expected/actual behavior and a screenshot with sensitive paths cropped if desired. Do not send personal saves, credential descriptors or raw account metadata.

Compared with `npm run browser`: the packaged EXE embeds Electron, Node, UI, indexing worker and service, works without the source checkout or developer PATH, and uses an isolated build-specific profile. Browser mode requires the development toolchain and uses its configured development storage. Both use the same bridge and UI; neither gains gameplay control. The optional standalone MCP process is the only packaged component requiring an external Node runtime.

This build is for personal acceptance, not a release certification. Native loaded-save behavior, current-focus/progress interpretation, full inventories and native gameplay control remain unqualified. Real HOI4 testing requires the separate bounded laptop plan.
