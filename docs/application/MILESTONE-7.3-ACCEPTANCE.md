# M7.3 Windows acceptance — provisional planning

This is an isolated development build. Extract the entire ZIP into a new folder, then run its commit-labeled HOI4 Companion executable inside win-unpacked. Keep the resources and DLLs beside it. Do not copy files over an existing installation. No installer, updater, release, HOI4 launch or game command is involved. Each build uses its own development profile; it does not import older companion data automatically.

1. Open Sources & settings. Confirm the installed HOI4 folder/version and indexed definitions. This build analyzes base-game sources; detected mods are disclosed but their overrides are not merged. Do not change your game playset. A missing game installation must be resolved before source-backed planning.
2. Create a disposable companion workspace for Portugal, select its focus tree, and open Campaign planner. Apply the ordinary reviewed baseline if needed. Existing save files and mods are not required.
3. Under Build a whole strategy, confirm AI generation is unconfigured. Enter a natural-language objective. Preview AI source bundle to inspect exactly what would be sent. This operation is local.
4. For offline acceptance choose Start local draft, name it, add installed focuses and supporting recommendations, and Save and recheck strategy. Try reversing a prerequisite pair: the sequence must need correction, and copying it into a focus alternative must be disabled. Restore the order and save again.
5. Reopen the saved whole strategy, edit a recommendation, save and restart the app. The text and revision should survive. Compare two saved whole strategies: they must remain unranked. Draft focus sequence as alternative copies its sequence and assumptions into the ordinary planner, where Preview/Apply still controls saving. It does not execute focuses or change completion history.
6. Optional, when ready: open AI provider configuration. Use an OpenAI API key from your own API account and an available structured-output-capable model. Enter the key only in the app. It is held in service memory, not persisted; Forget API key or closing the app removes it. No credentials ship with this build. No model is selected for you beyond an editable suggested model ID.
7. Review API pricing in AI-PROVIDERS.md. Output limits are token limits, not dollar caps. Configure account spending controls. Generation can incur charges even if it times out, is cancelled, or fails local validation. There is no automatic paid retry.
8. Preview the source bundle, approve transmission, then Generate provisional strategy. Only the previewed objective, country/source context, derived summaries, manual DLC assertions, optional typed campaign text and saved proposal for revisions are sent. Raw saves, logs, notes and observations are not sent automatically. Do not paste private save contents into the text fields.
9. For Portugal, inspect the restoration route, monarchist decisions and Brazil event references. All model wording is provisional; deterministic source mechanics and coverage gaps are shown separately. An eight-focus structurally valid route still has major unresolved political, civil-war and event conditions. Neither an existing citation nor a recent observation validates numerical benefits or an optimal strategy.
10. Save edits before requesting an AI revision. Enter revision instructions, preview the updated context and generate again. The prior saved document remains available. Export local evaluation history only after checking it for private objectives/manual text.

Real-provider generation and subjective strategic usefulness are not qualified in this build: the user chose to configure later. Deterministic provider fixtures exercise the workflow but are not real model output. If a provider rejects authentication/model access, inspect the account and configuration; do not launch HOI4. If source revision changes, save/review again. Missing IDs and wrong reference types reject instead of being guessed. Cancellation stops local waiting and cannot reverse provider charges.

The packaged app runs its own embedded local service without Node/npm on PATH. npm run browser builds and opens the source checkout's browser service and uses development/runtime environment configuration; it does not give the same commit-isolated Electron profile or packaged-runtime evidence. Both use the same Node planner, SQLite and coverage policy. Never point a test build at your regular application data directory.
