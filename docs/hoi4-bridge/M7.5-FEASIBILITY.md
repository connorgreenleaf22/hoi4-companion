## Proposed staged experiment

1. Separate authorized M7.5 task and written bounded plan. First finish noninvasive native qualification in M7-NATIVE-PLAN.md; a save/UI baseline is useful for memory validation. Review exact upstream diff/license and executable identity; preserve refusal for unknown hashes.
2. Offline reader harness: define an observation-only provider for GameObservation, injectable bounded memory-region reader, immutable compatibility manifest, unit fixtures for invalid pointers, access denied, short reads, process exit, allocation changes and repeated reads. No gameplay exports or fallback writes.
3. Owned disposable process metadata only: retain handle; bind process creation identity, executable path/hash and test lease. No elevated blanket system access; refuse rather than request debug privileges by default. Demonstrate stop/timeout/cleanup first.
4. Separately approve a narrowly scoped read-only game-memory experiment. Read only reviewed bounded committed regions with least privilege, validate counts/offsets twice, enforce wall/byte limits, and discard data on process/version/generation changes. Do not scan unrelated processes or dump entire memory. No PROCESS_VM_WRITE, remote threads, DLL loading, hooks or executable changes.
5. Start with one scalar country/date value with a documented layout for this exact executable. Compare independent paused UI/save evidence on two distinct states, including negative/version cases. Then current focus/research slot identity if stable. Preserve every failure as unsupported; never infer offset validity because a plausible number appeared.
6. Publish through the existing platform provider seam as unqualified until field-level review. Reuse existing ownership, gateway and receipt system. Command execution remains disabled. Invasive designs require an additional explicit technical/safety approval, not implicit escalation from a read-only failure.

Planning estimates (engineering judgment, not upstream promises): offline provider/ownership harness 2–4 days; one exact-build field reader 3–10 days if layouts are available; independently qualified focus/research 1–3 additional weeks. Linux porting or injection-based adaptation is a separate multiweek investigation with uncertain feasibility. Prefer a maintained exact-build read-only adapter if one becomes available; no current candidate clears all gates.
